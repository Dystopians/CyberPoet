## 一、目标与硬约束

在 Qwen3-14B 上做一个中文现代诗写作模型。**唯一目标是文学质量**；
项目主人明确表示其他能力退化完全可接受，也不介意模型记住训练语料。

**语料**：12 位中文现代诗人（洛夫、海子、昌耀、穆旦、多多、张枣、商禽、痖弦、
卞之琳、陈舸、冯至、王炜）共 2200 首，**37.3 万词元 / 1591 首**进入训练集。
中位长度 **134 词元**，90 分位 399，99 分位 2033，最长 10358。
语料版权在有效期内，不外传。

**硬件**：8 × RTX 6000 Ada（48 GB，无 NVLink，PCIe），与其他 3 位用户共用。
**当前可支配 3 张卡**（其余被他人长期占用）。`/data` 28 TB 已用 99%，余 340 GB。

**软件**：Python 3.11.15 / torch 2.7.1+cu126 / transformers 4.56.2 / PEFT 0.18.0 /
bitsandbytes 0.47.0 / accelerate 1.10.1 / LLaMA-Factory v0.9.5。
**未安装 deepspeed。**

## 二、已确证的结论（均有统计检验）

评价方式：项目主人**本人**盲标同题配对（左右随机、模型名不可见），
三批合计 **259 对**，其中有明确胜负 172 对、判「两首都不值得留」87 对。
**不使用任何模型作为文学评委**——项目早期的 AI 评审给出的结论后被证明方向相反。

1. **未适配基座在文学上完败**：2 胜 68 负（p = 4×10⁻¹⁸）。
2. **继续预训练有效**：预训练 1 轮打基座 9:1（p = 0.022）。
3. **形式服从可以修好**：20 道形式探针 × 6 种子 = 120 配对单元，McNemar 检验，
   最终版本在行数/节数/每节行数/字数/禁词/结尾六个维度上**均不显著劣于基座**。
4. **形式与文学存在取舍**：为修好「结尾服从」而做的数据分层，
   文学上以 1:14 输给了未做该分层的版本（p = 0.0010）。
5. **机械评分器在关键场景失效**：项目自建的 `quality_score` 与主人的一致率——
   跨模型比较 80–87%，**同一模型两次采样之间 49%（等于随机）**。

## 三、核心诊断：模型没有学到诗人的用词

分词后统计（语料 19.8 万词次 / 3.9 万词型）。

**1. 机器口音**（已剔除题面自带的词；倍数 = 模型每万词 ÷ 语料每万词）：
碎玻璃 115×、台阶 62×、吞下 30×、裂缝 29×、咳嗽 29×、传来 25×、腹中 22×、
尽头 15×、某种 15×、金属 12×。

**2. 整个陈述/形而上语域缺失。** 语料常用（≥5/万）而模型**一次未用**：
如果、肉体、多少、她们、草原、歌唱、永恒、诗歌、上帝、这么。
显著少用：我们 2.9×、太阳 6.1×、你们 11.1×、死亡 7.1×、诗人 28×、
头颅 11.7×、为了 11.3×、不能 10.1×、孤独 7.7×、痛苦 7.4×、历史 4.8×。
**模型只会写"小物件 + 动作"一种语域**，而穆旦、昌耀、海子大量使用另一种。

**3. 诗人标志词覆盖近乎为零。** 取每位诗人相对其余诗人显著超用的前 8 词：
洛夫 1/8、海子 1/8、昌耀 0/8、穆旦 1/8（这四位占语料篇幅最大，合计 3/32）。

**4. 搭配"新得没有依据"。** 相邻实词对在语料中从未出现的比例：
真实诗 94.3%、主人选中的 96.0%、主人弃选的 97.9%。
一对之内选中方更接近语料已有搭配（56:82，p = 0.033）。

**5. 但方向一致**：主人选中的诗与语料的 KL 距离 1.839 < 弃选 2.051 < 双负 2.263，
单调。「往语料靠」与「往主人偏好靠」不冲突。

## 四、怀疑的机制与已做的排除

### 已排除：采样参数

假设：全部生成用的 `repetition_penalty=1.08` 压制了诗人式的篇内词汇复现。
**消融（同题同种子，只改该参数）否定了它**：

| | 篇内重复率中位 | 最高频词次数 |
|---|---:|---:|
| rp = 1.08 | 0.194 | 3.0 |
| rp = 1.00 | 0.407 | 5.0 |
| 真实诗人 | 0.106 | 3.0 |

关掉惩罚使模型远超真实诗人的重复水平（退化为复读）。按模型分列（均用 1.08）：
cons 0.117、v2late 0.112、pt_sft 0.110 已与真实诗人（0.106）齐平，
**未适配基座是 0.000**。这一维训练是成功的。

### 主要怀疑：LoRA 的作用面

现行配置（LLaMA-Factory）：

```yaml
quantization_bit: 4          # nf4 + double quant
finetuning_type: lora
lora_target: all             # 展开为 q,k,v,o,gate,up,down 七个投影
lora_rank: 32 / lora_alpha: 64
# modules_to_save: None      ← 关键
```

Qwen3-14B 的 `tie_word_embeddings: False`，`embed_tokens` 与 `lm_head`
各 151936 × 5120 = **7.78 亿参数，合计 15.6 亿、占全模型 10.5%，此前完全冻结**。
决定"下一个 token 吐什么"的读出层从未训练，而诊断指向的正是词汇层。

## 五、显存账（**请重点审核**）

### 5.1 已实测

| 配置 | 实测峰值 | 结果 |
|---|---:|---|
| QLoRA rank32，cutoff 2048，batch1，梯度检查点 | ≈ 14 GB | 正常 |
| 上述 + `additional_target: embed_tokens,lm_head` | **> 47 GB** | **OOM** |
| 上述改为仅 `lm_head` + cutoff 1536 + `expandable_segments` | **45.9 GB** | 勉强通过，余量 1.5 GB |

OOM 触发点是长样本的 logits：`seq_len × 151936` 词表，
序列 2033 时单个 bf16 张量 0.62 GB，反传时同时存在多份。

### 5.2 14B 全量训练的估算（3 张 48 GB，FSDP 全分片）

| 方案 | 权重 | 梯度 | 优化器 | 合计 | 每卡 |
|---|---:|---:|---:|---:|---:|
| AdamW fp32 + fp32 主权重 | 29.6 | 29.6 | 118.4 + 59.2 | 236.8 | 78.9 ❌ |
| AdamW fp32，无主权重 | 29.6 | 29.6 | 118.4 | 177.6 | 59.2 ❌ |
| **8-bit AdamW，无主权重** | 29.6 | 29.6 | 29.6 | **88.8** | **29.6** ✅ |
| 8-bit AdamW + 优化器 CPU 卸载 | 29.6 | 29.6 | → CPU | 59.2 | 19.7 ✅ |

（单位 GB，P = 14.8 B）
再加激活（batch 1 / seq 1536 / 梯度检查点）约 2–4 GB、
通信缓冲与碎片 3–5 GB → **每卡 35–39 GB**，48 GB 可容。

### 5.3 请审核者判断的问题

1. **上述估算有无遗漏**？特别是 FSDP 的 all-gather 临时缓冲、
   以及 `lm_head` 在 151936 词表下的 logits + 交叉熵峰值。
2. **bitsandbytes 8-bit 优化器与 FSDP 全分片配合是否可靠**（torch 2.7.1，无 deepspeed）？
   若不可靠，优化器 CPU 卸载在 PCIe（无 NVLink）下的吞吐损失有多大？
3. **是否有更省的等效路径**？我们考虑过但未验证：
   - 只解冻 `lm_head` + 末 N 层，其余保持 LoRA（单卡可行）
   - 分块交叉熵 / fused CE（如 Liger-Kernel、cut-cross-entropy）
     以消除 `seq × 151936` 的 logits 峰值
   - 词表裁剪：语料仅覆盖约 2 万个中文 token，
     裁掉未出现的 13 万个可将 embed/lm_head 从 15.6 亿降到约 2 亿
4. **数据量是否根本不足**？37.3 万词元、1591 首。
   全量训练能否在这个量级上学到诗人标志词（多数词在全语料出现 12–30 次），
   还是必然过拟合到无法生成的程度？
5. **按诗人分开训练**（12 个小适配器）与**混合训练 + 提示词条件**，
   哪种更可能提升标志词覆盖？

## 六、性能现状（**请重点审核**）

| 任务 | 配置 | 实测速度 |
|---|---|---|
| QLoRA 继续预训练 | 单卡，batch1，累积8，cutoff 2048 | 4.7 s/step，199 步/轮 ≈ 16 分钟/轮 |
| QLoRA + lm_head | 单卡，cutoff 1536 | 5.1 s/step |
| 14B 推理（bf16，非量化） | 单卡 batch 8 | 约 13.9 GB，约 25 s/首（560 max_new_tokens） |

已知的低效：

- **`packing: false`**。诗中位仅 134 词元而 `cutoff_len` 设到 1536–2048，
  每个 batch 绝大部分是 padding。开 packing 可大幅提升吞吐，
  但会把不同诗人的作品拼进同一条序列——**是否值得？有无 `neat_packing`
  之外的做法（如按长度分桶 + 动态 padding）？**
- **梯度累积 8、batch 1**。在 48 GB 卡上 seq 134 的样本完全可以 batch 8–16，
  是否应改为按 token 数动态成批？
- 未使用 flash-attention 之外的任何 kernel 优化（`flash_attn: auto`）。
