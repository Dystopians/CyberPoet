# 标注工具与制作思路

仓库里有两份可直接用浏览器打开的标注页：

| 文件 | 内容 |
|---|---|
| `labeler/标注_第一批_131对.html` | 跨模型对打，用来验证 AI 评审是否可信 |
| `labeler/标注_第二批_80对.html` | 24 对选基础模型 + 56 对同模型采样（DPO 用） |

两份里嵌的全部是**模型生成的诗**，与语料的最长逐字重合实测为 **0 字**，故可公开。

## 为什么要人来标

项目此前所有文学结论都出自 AI 评审，而 2026-08-25 的实测证明它的判断是**反的**
（详见 `04-偏好标注与DPO.md`）。因此规矩是：只报可数的东西，诗交给人读。
标注工具存在的意义是让"读"这件事顺带产出可训练的数据。

## 界面上的三个决定

**一、两选一，不做四选一。** 曾提议"一次读 4 首、选出最好与最差"以节省一半时间，
项目主人否决，保持 A/B。不要再提。

**二、第三个键的语义是"两首都不值得留"，不是"平局"。** 第二批起判据抬高为：

> 先问「这首我会留下吗」，再问「哪首更好」。
> 只要两首都不值得留就按 ↓——哪怕其中一首明显没那么烂。

理由是 DPO 只学一对之内**不一样**的东西，两首共有的毛病它完全看不见。
用标注者的时间去区分两坨垃圾，训出来的是一个更稳定的平庸模型。

**三、标注期间不暴露模型身份。** 左右顺序随机，页面只显示"甲/乙"，
gen_id 导出后才对得上号。标注进行中也不要口头告知——会影响剩余判断。

## 配对的六条规则

1. 按 `(题目, 去空白正文)` 去重，**不按元数据哈希**。带来源和种子的哈希会漏网：
   实测 800 条池子里漏了 36 条。
2. **一条生成一批里只用一次**。首批因为没管这个，34 首诗被标注者看了两遍
   （262 个槽位里只有 217 首不同的诗）。
3. 两侧四字窗口 Jaccard ≥ 0.8 直接跳过——两首几乎一样，标了没信息。
4. **`model` 字段里不许塞非模型的东西**。曾把"机械检查合格/被拒"当成两个模型，
   造出 7 对假的跨模型配对。
5. **标注前不做任何机械分数预筛**（`01-现状与关键结论.md` 第七节）。
6. N 对需要约 N 个不同题目、每题至少 2 个模型（或 2 次采样）的输出。

## 一批任务由两部分组成

**A 部分 · 选基础模型**：几个候选模型同题对打，轮转搭配，同一题内不重复用同一首诗。
第二批是 12 道题 × 2 对 = 24 对，覆盖 base / sft_v2 / 预训练 2 轮 / 预训练+修复微调。

**B 部分 · 同模型采样**：选定模型对同一题采样 4 次（同参数、不同种子），
拆成 2 对不相交的配对。**这才是 DPO 真正要吃的数据**——教的是
"同样的你，为什么这次写得好、那次写得差"。

第一批的教训：97% 的决定性标注都是"某模型打赢基座"，那种数据教的是
"别像基座"，而基座不会出现在后续任何一版里。

## 标完之后看什么

1. **双负率**。超过一半说明模型还不配占用标注者的时间——应该先改模型，别标。
2. **A 部分的胜负** → 直接定出 DPO 的基础模型。选错会浪费整批标注。
3. **B 部分里"你选的"和"没选的"差在哪** → 这是 DPO 能学到什么的直接预告。
4. 与 `quality_score` 的一致率（首批 75%）→ 决定那些机械规则该不该留。

## 复现命令

```bash
# 1. 生成候选（A 部分四模型对打 / B 部分同模型多采样）
python scripts/preference/gen_batch2.py --part A --n 12 --out batch2_A.jsonl
python scripts/preference/gen_batch2.py --part B --n 30 --samples 4 --out batch2_B.jsonl

# 2. 组配对（自带去重、不重用、近重复过滤）
python scripts/preference/make_pairs2.py

# 3. 生成单文件网页
python scripts/preference/make_labeler2.py
```

旧的一套（`build_bank.py` / `make_pairs.py` / `make_labeler.py`）用于把历史生成
收拢成池子再配对，适合"手头已经有一堆生成"的场景。

## 标注结果的存放

页面把进度存在浏览器 localStorage，点"导出标注"得到 JSON：
`[{prompt_key, A: gen_id, B: gen_id, choice: "A"|"B"|"tie"}]`。
`choice: "tie"` 即"两首都不值得留"。

## 第三批（2026-08-26）

`labeler/标注_第三批.html`，**84 对**：

| 部分 | 对数 | 内容 |
|---|---|---|
| A · 选基础模型 | 24 | 12 题 × 四模型两两轮转，六种组合各 4 对 |
| B · 同模型采样 | 60 | `cons` 对 30 题各采样 4 次，拆成互不相交的配对 |

A 部分的四个模型：未适配基座、预训练2轮、预训练3轮+修复微调、
**预训练2轮+纯约束回放**（新增，见 `08-形式服从实测.md`）。

B 部分选 `cons` 的理由是**可数的**：120 个配对单元的实测显示它把行数服从从
预训练2轮的 56 拉回 81（基座 77）、每节行数拉到 84（基座 73）、禁词保持 119/120，
是唯一在约束维度上不显著劣于基座的候选。**文学取舍仍由标注决定，不由这些数字决定。**

自检结果：
- 重复使用的生成 **0 条**（规则 2）
- 页面内不含任何 `model` 字段，只有 `id` 与正文（规则：标注期间不暴露身份）
- 168 首诗对 1757 篇原诗的**最长逐字重合 0 字** → 可公开入库
- 标注前**未做任何机械分数预筛**（规则 5）

复现命令：

```bash
python scripts/preference/gen_batch3.py --part A --n 12 --out preference/batch3_A.jsonl
python scripts/preference/gen_batch3.py --part B --n 30 --samples 4 --model cons --out preference/batch3_B.jsonl
python scripts/preference/make_pairs3.py --b-model cons
python scripts/preference/make_labeler3.py
```
