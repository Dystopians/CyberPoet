## GPU 规矩

机器是 8 卡 RTX 6000 Ada（48 GiB），与其他人共用。

- **看到空卡立刻占**：`nvidia-smi` 显示某卡 ≈0 MiB、0% 就直接
  `CUDA_VISIBLE_DEVICES=<n>` 启动，**不要**套 `scripts/gpu_gate.py`——
  它的 `--stable-checks 5 --interval 60` 要先等五分钟，等的过程中卡会被别人拿走。
- **绝不与别人的进程共用同一张卡**。启动前用
  `nvidia-smi --query-compute-apps=pid,used_memory --format=csv` 确认目标卡没进程。
- 一次 QLoRA 训练约占 13–14 GiB（cutoff 2048）；14B 推理约 13.9 GiB。

选空卡的一行命令：

```bash
nvidia-smi --query-gpu=index,memory.used,utilization.gpu --format=csv,noheader,nounits | awk -F', ' '$2<1024 && $3<10 {print $1; exit}'
```

## 与 codex 并行工作的规矩

另一个 codex 会话**实时改写** `cyberpoet_v1` 里的文件——实测它能在两分钟内
整份重写 `scripts/run_{sft,smoke,teacher}.sh`，默默丢掉别人的改动。

- **只读，不改。** 结论写成新文件交接，不去编辑它的树。
- 记录所依赖脚本的 SHA-256（`SCRIPT_FINGERPRINTS.txt`），因为它的代码分钟级变动。
- 需要用它的脚本时，用它的脚本但把输出写到自己的目录（`--out`、`--out-dir`）。

## 常见坑

1. **`materialize_v3.py --targets` 的默认值指向作废文件**（`targets_raw.jsonl`，
   第一轮 40 条的废数据，仍原样躺在 `v3/data/`）。物化时必须显式写 `--targets`。
2. **打包（packing）会把多首诗拼成一条序列**，诗很短，不要开。
3. **截断是静默的**：数据最长 2317 词元，配置写 2048 就会切掉结尾且不报错。
4. **开发集必须按来源诗切**，不能随机切——同一首诗在三类任务里重复出现。
5. **教师标注不可信**：形式栏 81.6% 造假、物象栏 73.1% 不出现。凡是能从答案
   本身数出来的信息，就不要让模型猜。
6. **检查器要先用正反例验过再上线**。本轮有过一次检查器写错、把 649 条全标成
   问题的情况；判错的代价是整轮数据报废。

## 长期作业的挂法

用 `nohup setsid ... > 日志 2>&1 < /dev/null &`，这样断开会话也不会被杀。
等待链的写法见 `scripts/sft_repair/chain.sh`：轮询前一个作业的产物行数或进程
存活，齐了就扫空卡启动下一步。
